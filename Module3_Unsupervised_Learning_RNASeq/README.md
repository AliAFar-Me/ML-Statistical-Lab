# Module 3: Unsupervised Learning & Dimensionality Reduction

Pipeline for the $p \gg n$ problem, demonstrated on a Gene Expression Cancer
RNA-Seq dataset: **PCA → UMAP → K-Means (optimized) → DBSCAN (contrasted) →
visual + quantitative validation against held-out true labels.**

## Contents

```
Module3_Unsupervised_Learning_RNASeq.ipynb   # the notebook (raw nbformat 4)
data/
  gene_expression_data.csv                   # samples x genes matrix
  gene_expression_labels.csv                 # true cancer subtype per sample
```

## Data provenance — please read before using for a portfolio

This notebook is written against the structure of the UCI **"gene expression
cancer RNA-Seq"** dataset (801 samples × 20,531 genes, 5 classes: BRCA,
KIRC, COAD, LUAD, PRAD; sourced from TCGA PANCAN). The sandbox this module
was built in has **no network access**, so the real dataset could not be
downloaded here.

The included `data/*.csv` files are a **synthetic stand-in**, generated by
`generate_synthetic_rnaseq()` (embedded in the notebook itself). It matches
the real dataset's shape family (p ≫ n), its 5-class structure, and its
class balance, with genuine — but synthetic — cluster signal baked in via a
latent-factor model, specifically so every cell in the notebook is real,
executable, validated code rather than a hypothetical sketch.

**Before using this for your portfolio, swap in the real data:**
1. Download the real dataset (search "gene expression cancer RNA-Seq UCI" or
   pull the TCGA PANCAN RNA-Seq matrix from a source with network access).
2. Save it as `data/gene_expression_data.csv` (samples × genes, first column
   = sample ID) and `data/gene_expression_labels.csv` (sample ID → class).
3. Re-run the notebook top to bottom — no code changes are required; the
   loader (`load_gene_expression_data()`) automatically prefers real files
   over the synthetic fallback.

The pipeline logic, PCA/UMAP/K-Means/DBSCAN configuration, and all narrative
Markdown are written for the real dataset's known properties (~20k genes,
5 known cancer subtypes) and are not synthetic-data-specific.

## Validation performed

- Every code cell's *actual* source, as shipped in the `.ipynb`, was
  executed end-to-end against the included synthetic dataset in a sandboxed
  Python environment and confirmed to run without errors (see the
  "Structural check" / cell-by-cell execution used during development).
- `umap-learn` could not be installed in the build sandbox (no network
  access). The notebook's UMAP cell uses the real, standard `umap.UMAP` API
  and was validated separately against a stub implementing the same
  interface to confirm all downstream shape handling and plotting logic is
  correct. **You will need `pip install umap-learn` in your own environment
  before running the notebook** — it is not part of the Python standard
  library or a default scikit-learn/pandas install.
- On the included synthetic data, the pipeline recovers the 5 true classes
  essentially perfectly (silhouette-selected k = 5, ARI = NMI = 1.0) — this
  is expected of the synthetic generator's clean latent structure and is
  not a claim about performance on real TCGA data, which will be noisier
  and where perfect recovery should not be expected.

## Key design decisions (why, not just what)

- **True labels are separated in Section 1 and not referenced again until
  Section 5.** This keeps the entire pipeline honestly unsupervised.
- **K-Means and DBSCAN both cluster on the PCA-reduced space, never on the
  2D UMAP projection.** UMAP distances are locally, not globally,
  meaningful — clustering on them risks manufacturing artifacts of the
  projection rather than the data.
- **`k` is chosen by silhouette score, cross-checked against the elbow
  curve** — not eyeballed.
- **DBSCAN's `eps` is derived from a k-distance-graph heuristic and then
  stress-tested with a percentile sweep**, to make the "density algorithms
  struggle in high dimensions" claim a demonstrated result, not an assertion.
